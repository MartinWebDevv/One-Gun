# One Gun Art and Asset Audit

## Summary

One Gun mixes four asset pipelines:

1. Original low-poly procedural assets generated by repository Blender scripts.
2. Imported character/animation and weapon assets without repository source files.
3. Legacy/downloaded environment and Western assets, including a documented Tripo set that was heavily optimized.
4. Procedural Godot geometry/materials used for gameplay readability, effects, and placeholder presentation.

The three current maps have distinct visual identities and the generated Forest/Western V2/City assets are small and reproducible. The largest art risks are source/provenance continuity, the very heavy orange bot character, duplicated animation textures, missing `.blend` files, missing license/attribution records, and several clearly provisional VFX/UI/world visuals.

## Current character audit

### Cat mascot/player

Primary scene/model:

- `player.tscn`.
- `models/playerAnimations/cat model firing ani.glb`.

Verified model characteristics:

- One armature.
- One imported action in the base GLB.
- Approximately 33,376 triangles and 20,361 vertices.
- One 2048x2048 `cat colors` texture.
- Four imported materials: `CAT MAT.001`, `CAT MAT.002`, `Dots Stroke`, and `Material`.
- Right/left skeleton hand attachments are authored in `player.tscn`.
- Gun, melee, and item hold markers are children of the right-hand attachment.
- The animation player's root-motion track targets the Mixamo hips bone, though movement itself is controller-driven.

Animation source:

- `models/playerAnimations/Dance.glb` contains one armature and 11 actions.
- Runtime code maps action-list indices to idle, movement, pistol, jump, roll, death, and dance names.
- Twelve individual animation GLBs and twelve zero/small-size generated `.tscn` wrappers remain in the animation folder.

The cat is a functioning, rigged gameplay character, not a placeholder primitive. It should not be modified during unrelated work. Preserve the armature, bone names, animation ordering, scale, materials, and hand-attachment paths until a dedicated character pipeline phase is approved.

### Bot character

Primary scene/model:

- `DummyModel.tscn` -> `botmodel.tscn` -> `models/new guy one gun model orange running.glb`.

Verified characteristics:

- One armature and one imported action.
- Approximately 660,636 triangles and 337,130 vertices.
- Four 2048x2048 images.
- Approximately 24.67 MB for the GLB alone.

This model exceeds the repository's own guideline that anything over about 10 MB requires optimization and is far beyond the suggested character/prop density. Because bots can fill an eight-actor match, this is a high memory/render/import risk. This audit does not alter it.

## Blender pipeline

### Installed tool

- Shortcut target: `D:\Blender\blender.exe`.
- Verified version: Blender 5.1.2.
- Generator comments target Blender 5.x and match the installed major version.

### Source files

No `.blend` files exist in the repository.

Consequences:

- Procedurally generated map/item assets are reproducible from Python.
- Imported character, animation, weapon, legacy environment, and legacy Western assets are not reproducible from repository source.
- Rig/material/export changes to imported assets require an external original or round-tripping the GLB.

### Generators

| Script | Output folder | Output count | Determinism/notes |
|---|---|---:|---|
| `tools/gen_forest_assets.py` | `models/forestAssets/` | 32 GLBs | Explicitly seeded; intended deterministic reruns |
| `tools/gen_western_assets.py` | `models/westernV2/` | 19 GLBs | Fixed per-asset seeds and low-poly geometry |
| `tools/gen_city_assets.py` | `models/cityAssets/` | 30 GLBs | Fixed seeds for randomized forms |
| `tools/gen_item_assets.py` | `models/items/` | 3 GLBs | SmokeBomb, Boomerang, DecoyBag |
| `tools/render_preview.py` | External temp screenshot | Contact sheet | City-only preview with a hardcoded Claude scratch path |

All generator output directories are hardcoded to `D:\Godot Projects\one-gun\...`. The scripts do not resolve the repository relative to `__file__` and do not accept command-line output arguments. They are consistent on this machine but not portable.

### Map builders

- `tools/build_forest_map.gd` creates ForestMap through a temporary autoload workflow.
- `tools/build_western_v2.gd` creates WesternV2Map through the same pattern.
- `tools/build_city_map.gd` created CityMap, but project history explicitly marks it retired because City is now user-tuned and should receive surgical edits only.

The builders can overwrite full scenes. They are not ordinary runtime tools and should never be run casually against hand-edited maps.

### Legacy optimization pipeline

Project history documents that 21 Tripo Western assets originally totaled about 19.5 million triangles and 665 MB, causing editor crashes. They were simplified with glTF Transform and textures were reduced to 1024/2048 resolution, with originals backed up outside the repository at `D:\Godot Projects\one-gun_originalAssets_backup\`.

The written budget is sound and should remain a protected intake rule:

- Inspect every new GLB over approximately 10 MB.
- Props: target <=15k triangles and 1024 textures.
- Buildings/landmarks: target <=100k triangles and 2048 textures.

## Godot import/material pipeline

- GLBs are referenced directly as `PackedScene` resources.
- Godot maintains per-source `.import` metadata and extracted textures.
- Melee visuals are selected by path from runtime `WeaponData` and instanced into `melee_weapon.tscn`.
- The generic melee scene's authored MeshInstance is a container/placeholder and is replaced with the rolled model.
- Powerups, bullets, several hazards, and HUD visuals use StandardMaterial3D/procedural mesh resources.
- The shared UI theme is both stored as `one_gun_theme.tres` and rebuilt by script.

## Duplicate files

Exact-hash scan found 11 duplicate groups outside generated metadata.

Notable duplicates:

- Thirteen separate `*_cat colors.png` files are byte-identical at about 559 KB each. They accompany each animation GLB and duplicate roughly 7 MB of source texture data.
- Multiple `models/environment/` Albedo/Normal/Metallic files are exact duplicates across separate imported props. These may reflect how the original asset pack was exported.
- Some environment metallic maps are identical small/flat maps.
- Godot/Terrain3D may create `~libterrain...` hot-reload copies while the editor holds the native DLL; these are transient/untracked artifacts, not intentional source.

Root autosave duplicates:

- Two `game_setup.tscn*.tmp` files are exact copies of the current `game_setup.tscn`.
- Two `node_3d` temp files are exact copies of each other; other node temp files are distinct older snapshots.
- `item.gd - Copy.uid` is a stray UID artifact with no corresponding duplicate script.

This audit does not delete any duplicate or temporary file.

## Materials and visual consistency

Strengths:

- Forest, Western V2, and City each use cohesive generated palettes.
- Runtime powerup colors are consistent between world pickup and HUD status.
- Weapon/holder readability uses outlines, locators, emissive materials, and strong colors.
- New generated models stay within small file sizes.

Risks:

- Legacy realistic/AI assets and generated low-poly assets vary in density and style.
- Imported assets use inconsistent scale/orientation and require hand-authored transforms.
- Some item scales were estimated from bounds rather than visually documented.
- Runtime material duplication/overlays add hidden complexity that is not obvious from source scenes.

## Art pipeline wins to preserve

- Seeded generators provide cheap regeneration for original map assets.
- GLB paths are stable, so optimized replacements did not break scenes.
- The documented asset budget directly addresses a previously severe crash source.
- Current cat model is within a reasonable gameplay density and has working hand attachments/animation.
- The project already distinguishes generated map sets by folder and theme.
- Forest atmosphere combines lighting, fog, wind, particles, ambience, birds, pond interaction, and shooting stars coherently.

## Art risks requiring future decisions

1. Establish asset licenses/provenance before a public release.
2. Preserve external originals/backups for assets with no repository source.
3. Treat the orange bot model as the highest asset-budget risk.
4. Make generators portable before relying on them on another workstation.
5. Confirm all item/melee held scale and orientation next to the cat.
6. Decide which procedural/emoji visuals are intentional style and which are placeholders.
7. Reconcile duplicate animation textures only in a dedicated asset-maintenance pass; animation imports are fragile and should not be disturbed casually.
